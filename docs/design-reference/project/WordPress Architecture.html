WordPress theme architecture & handoff

How this portfolio translates into a custom, production-ready WordPress theme — fully manageable from wp-admin, with no code edits to add a project or write a post.

Recommendation File structure Content modeling Customizer Tailwind build Contact form Standards & i18n Quick start
01 — The call

Classic theme + Tailwind

Recommendation: a custom classic theme (PHP templates + Tailwind).

It gives Naeem full control over markup and the asset pipeline, maps cleanly onto the template hierarchy, and keeps the door open to register blocks later. A full FSE/block theme would trade that control for theme.json-driven editing he doesn't need for a single-author site.

Classic + Tailwind CHOSEN

  • Total control over semantic markup & ARIA
  • Tailwind compiled once, scoped, cached
  • Familiar PHP template hierarchy
  • Can still register Gutenberg blocks
  • Smallest runtime JS footprint

Block theme (FSE)

  • Edit everything in the Site Editor
  • theme.json design tokens
  • Less PHP to maintain
  • — Harder to hand-tune markup/perf
  • — Tailwind fights the block CSS layer
02 — Layout

Theme file structure

Follows the WordPress template hierarchy. Assets are compiled into /assets/css and enqueued — never hardcoded.

naeem-portfolio/
├── style.css            # theme header + (optional) compiled tailwind
├── functions.php        # setup, enqueues, includes
├── header.php · footer.php
├── front-page.php       # the single-page layout (hero → contact)
├── index.php · home.php  # blog listing
├── single.php           # single post
├── page.php · page-resume.php
├── archive.php · category.php · 404.php
├── template-parts/
│   ├── hero.php · about.php · experience.php
│   ├── projects.php · opensource.php
│   ├── skills.php · blog.php · contact.php
│   └── card-project.php · card-post.php
├── inc/
│   ├── cpt.php           # register project CPT + taxonomy
│   ├── customizer.php    # hero, socials, skills, resume
│   └── enqueue.php
├── assets/
│   ├── src/tailwind.css · main.js
│   └── css/app.css   # compiled, committed
├── tailwind.config.js · postcss.config.js
├── package.json
└── languages/naeem-portfolio.pot
03 — Data

Content modeling, the WordPress way

Projects → custom post type

Register a project CPT with a tech custom taxonomy for the filter tags. Live URL and GitHub URL are post meta. Use the native block editor for the description and the featured image for the thumbnail — only reach for ACF if Naeem wants a fixed, labelled meta box (a soft dependency worth noting).

register_post_type( 'project', [
  'public'       => true,
  'menu_icon'    => 'dashicons-portfolio',
  'supports'     => [ 'title', 'editor', 'thumbnail', 'excerpt' ],
  'show_in_rest' => true, // block editor + REST
  'rewrite'      => [ 'slug' => 'work' ],
] );

register_taxonomy( 'tech', 'project', [
  'hierarchical' => false, // tag-like: PHP, Vue, MySQL…
  'show_in_rest' => true,
] );

Open Source → a taxonomy on projects, not a second CPT

Cleaner option: model the WordPress focus areas (Core, Plugins, Meta, Polyglots, Photos, EmDash) as a contribution_area taxonomy plus a Customizer-driven highlights block — rather than a whole second CPT. It keeps the admin simple while still giving the section the visual weight it deserves on the front end.

Blog → native posts

No custom anything. home.php lists posts, single.php renders one, archive.php / category.php handle taxonomies. Standard, SEO-friendly, Yoast/Rank Math compatible.

Résumé → a page template

page-resume.php renders an inline web résumé and a Download PDF button. The PDF is uploaded via the Media Library and linked from a Customizer setting, so Naeem swaps it without touching code.

04 — Editable

Customizer settings

Everything that isn't a project or a post lives in the Customizer, fully sanitized:

  • Hero — name, rotating role lines, one-liner, CTA labels & links
  • Social links — GitHub, LinkedIn, email
  • Skills — grouped lists (Backend, Frontend, Databases, Tools/AI)
  • Experience — repeatable timeline entries (or a lightweight CPT if Naeem prefers)
  • Résumé PDF — Media Library file, linked from the hero & résumé page
$wp_customize->add_setting( 'naeem_hero_oneliner', [
  'sanitize_callback' => 'wp_kses_post',
  'transport'         => 'postMessage',
] );
05 — Build

Tailwind build step

Tailwind compiles via the CLI into a committed stylesheet, scoped with a prefix and important root so it never bleeds into wp-admin. The compiled file is enqueued like any other asset.

// package.json
"scripts": {
  "dev":   "tailwindcss -i assets/src/tailwind.css -o assets/css/app.css --watch",
  "build": "tailwindcss -i assets/src/tailwind.css -o assets/css/app.css --minify"
}

// functions.php — enqueue, never hardcode
add_action( 'wp_enqueue_scripts', function () {
  wp_enqueue_style( 'naeem-app', get_theme_file_uri( 'assets/css/app.css' ), [], '1.0.0' );
  wp_enqueue_script( 'naeem-main', get_theme_file_uri( 'assets/src/main.js' ), [], '1.0.0', true );
} );
06 — Contact

Contact form: Fluent Forms

Recommend Fluent Forms — it's lightweight, has clean markup the theme can style, and it's built by WPManageNinja (a nice, on-brand touch). Drop the form via shortcode in template-parts/contact.php; the theme styles it to match. Contact Form 7 / WPForms remain drop-in alternatives if a client prefers them.

07 — Craft

Standards, i18n & SEO

  • Escape & sanitize everything — esc_html(), esc_url(), wp_kses() on output; nonces on the form.
  • i18n-ready — every string wrapped in __() / _e() with the naeem-portfolio text domain (he contributes to Polyglots — keep it spotless).
  • Theme supports — title-tag, post-thumbnails, custom-logo, html5; registered nav menus & widget areas.
  • SEO — clean semantic markup, schema-friendly structure, compatible with Yoast / Rank Math.
  • Accessibility — semantic HTML, ARIA, keyboard nav, WCAG AA contrast (the light & dark palettes in this design already clear it).
08 — Ship

Quick start (README)

Install the theme

Copy naeem-portfolio/ into wp-content/themes/ and activate it in Appearance → Themes.

Build the styles

Run npm install then npm run build (or npm run dev while editing). The compiled CSS is committed, so a fresh clone works without building.

Add a project

Projects → Add New: title, description, featured image, set Tech terms, fill the Live URL & GitHub meta. It appears in the grid automatically.

Write a post

Posts → Add New as usual — it shows in the blog preview and the full blog listing.

Update the résumé & profile

Appearance → Customize: upload a new résumé PDF, edit hero copy, skills, and social links.

Configure the contact form

Install Fluent Forms, create the form, paste its shortcode into the contact section setting.

Generate translations

Run WP-CLI wp i18n make-pot . languages/naeem-portfolio.pot to regenerate the .pot for translators.
